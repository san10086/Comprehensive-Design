# 空间音效处理算法研究与实现

## P01 研究目标与开发过程

### 页面内容

**目标：利用 HRIR 双耳卷积，在 ARM/DSP 音频链路中实现可选方向的空间音效。**

\[
y_L=x*h_L,\qquad y_R=x*h_R
\]

| 开发阶段 | 主要工作与产物 |
|---|---|
| 原理复现 | MATLAB 读取声源与左右耳 HRIR，完成卷积、双声道输出与试听准备 |
| 数值基准 | 纯 C Q15 直接卷积，统一舍入、饱和与分块历史，建立独立参考 |
| DSP 集成 | 浮点 FFT 重叠相加，经 `AudioAlgo` 接入 ARM/SysLink/DSP 主链路 |
| 功能扩展 | 固定方向与动态过渡，扩展到 MIT KEMAR 方位库及可配置双声源 |

**当前进展：从两组固定 HRIR，扩展到 710 个离散方向，并贯通方向参数的配置链路。**

### 汇报讲稿

研究工作先围绕双耳卷积建立原型，再用纯 C 定点版本明确数值规则，最后以 FFT 分块实现接入 DSP。原有工程只使用两组固定响应，本阶段进一步导入 MIT KEMAR 系数库，让方向选择通过参数传入算法，并扩展双声源的独立方向配置。上述阶段按实现用途组织，Q15 基准与 FFT 模块在同一空间算法提交中加入。

## P02 MIT KEMAR 系数导入与参数贯通

### 页面内容

**系数库导入**

- 1420 个方向 HRIR WAV 配成 **710 组双耳响应**，覆盖仰角 **−40° 至 90°** 的离散采样点。
- 逐文件校验：**44.1 kHz、单声道、PCM16、512 点**；检查左右耳配对、重复方向和非法角度。
- 自动生成方向目录与 DSP 系数，保持原始样本顺序和幅值；11 个耳机/扬声器响应文件不作为方向数据导入。
- 系数共 **1,454,080 字节，约 1.39 MiB**；ARM 保留方向目录，DSP 按当前方向缓存频谱。

**参数接通**

`仰角/方位角参数 → ARM 目录校验 → SysLink 方向发送与 ACK → DSP 选取双耳系数 → FFT 卷积`

```sh
# 开发机：生成并校验系数
make hrir
make hrir-check

# 板端：查询方向；只校验参数，不启动 DSP
./run.sh directions
./run.sh audio --seconds 10 --algo spatial --elevation -40 --azimuth 45 --check
```

### 汇报讲稿

导入工作的重点是把方向数据组织成可重复生成、可查验的系数目录。比如 `L-40e045a.wav` 表示仰角负 40 度、方位角 45 度的左耳响应。单声源接收一组方向，双声源分别接收 A、B 两组方向，ARM 与 DSP 使用同一目录和稳定编码。方向发送后核对确认码，再配置算法。当前采用库内方向精确匹配，一次运行内方向固定。

## P03 试错与算法选型

### 页面内容

| 试错或实现难点 | 处理与选择理由 |
|---|---|
| 旧输入扩展名为 WAV，实际是 M4A | 检查真实文件格式，统一为 PCM16 / 44.1 kHz，避免将解码问题误判为算法问题 |
| MATLAB 试听输出可能整体归一化 | 另建 Q15 参考，统一舍入与饱和，以逐样本结果判断正确性 |
| 分块计算与原地写回容易破坏连续性 | 保留 511 点状态，短块保留未消耗尾部，读取输入后统一写回 |
| 从两方向扩展到完整方位库 | 自动生成与配对校验，使用稳定方向编码，拒绝不存在的方向 |

**选型：Q15 直接卷积作为数值基准，DSP 使用浮点 FFT + overlap-add。**

- 最大输入块 1024 帧、HRIR 512 点，线性卷积需 **1535 点**，选用 **2048 点 FFT**。
- 复用输入频谱和已准备的 HRIR 频谱；保留直接卷积用于对照。
- 原始系数约 1.39 MiB，频谱按需缓存，避免为全部方向常驻保存 FFT 结果。

### 汇报讲稿

试错主要集中在输入格式、数值规则和块间连续性。旧文件格式与扩展名不一致，整段归一化也会干扰数值比较，因此先固定数据和计算约定。FFT 长度则由输入块和滤波器长度共同决定。保留直接卷积便于核验，DSP 使用 FFT 减少长 FIR 的重复计算。实际加速幅度和实时预算需要目标板计时，当前不填未经测量的性能数字。

制作备注：当前 `input.wav` 已是标准 PCM WAV，旧格式对应 `input_old.wav`。HRIR 保持自然顺序，与 `x[n-k]h[k]` 的索引方式一致。短块与覆盖问题作为设计难点讲述，不虚构历史故障截图。本页不安排配图。

## P04 已实现功能：指定方向与动态过渡

### 页面内容

**运行条件：以下为板端命令，假定 ARM/DSP 已成套构建部署，输入为 44.1 kHz、双声道 PCM16 WAV。**

**① 指定方向渲染：双声道平均为一个声源，通过仰角、方位角选择 HRIR。**

```sh
./run.sh file --input input.wav --output midterm_spatial.wav \
  --algo spatial --elevation 60 --azimuth 250
aplay -D default midterm_spatial.wav
```

**② 采集、处理、播放：使用同一组方向参数驱动连续音频链路。**

```sh
./run.sh audio --seconds 10 --algo spatial --elevation -40 --azimuth 45
```

**③ 动态过渡：`40e045` 双耳输出与左右耳互换输出之间逐样本交叉淡化，往返周期约 4 秒。**

```sh
./run.sh file --input input.wav --output midterm_orbit.wav --algo orbit
aplay -D default midterm_orbit.wav
```

### 汇报讲稿

单声源模式把左右输入平均成同一个声源，再按选择的方向进行双耳渲染。文件模式先输出结果、后独立播放，方便检查算法输出；audio 模式接入采集和播放，作为后续实时验收入口。动态模式通过权重变化在一组响应及其镜像之间往返，适合演示双耳效果的连续变化。当前方位库提供离散方向选择，orbit 仍保持原有镜像过渡实现。

制作备注：工程采用仰角 0° 为水平、90° 为头顶，方位角 0° 为前、90° 为右、180° 为后、270° 为左的约定。710 个方向是离散点，不代表任意整数角都可用。orbit 的实现范围为镜像往返。本页以命令展示功能，不再添加终端或代码截图。

## P05 已实现功能：双独立声源与兼容模式

### 页面内容

**双独立声源：左输入为源 A，右输入为源 B，分别选择双耳响应后以 0.5 权重混合。**

\[
z_e=0.5(x_A*h_{A,e})+0.5(x_B*h_{B,e}),\quad e\in\{L,R\}
\]

```sh
# 文件渲染：A 选 60e250，B 选 40e045
./run.sh file --input dual_footsteps.wav --output midterm_dual.wav --algo dual \
  --a-elevation 60 --a-azimuth 250 --b-elevation 40 --b-azimuth 45
aplay -D default midterm_dual.wav
```

**原有固定模式继续保留，可直接复现既有演示。**

| 功能 | 对应命令 |
|---|---|
| 固定 `40e045` | `./run.sh file input.wav midterm_40.wav spatial40` |
| 固定 `60e250` | `./run.sh file input.wav midterm_60.wav spatial60` |
| 固定双声源 A=`60e250`、B=`40e045` | `./run.sh file dual_footsteps.wav midterm_dual_fixed.wav dual4060` |

### 汇报讲稿

双声源模式保留输入左右声道的独立性。每个声源各自完成双耳卷积，维护独立尾部，再混合成耳机的左右输出。导入方位库后，A、B 的方向都能通过命令参数选择，原来的双声源模式则保留为固定方向快捷入口。演示素材应把两个不同节奏的脚步声分别放在输入左右声道，便于比较单独声源和混合效果。

制作备注：`dual_footsteps.wav` 需事先准备两路不同素材。0.5 权重提供混音余量，输出继续饱和处理。具名参数 `--algo dual` 必须传 A/B 方向；旧位置语法保持固定行为，单次命令不要混用两种参数格式。试听其他输出时使用 `aplay -D default 输出文件.wav`。本页不安排配图。
